独立页面 PRD · open_id 接入说明

Lark 人员 - PRD

本项目使用国际版 Lark（Lark Suite），不是中国大陆版飞书。所有 Lark Open API 和开发文档统一使用国际版官方平台。API 域名固定为 https://open.larksuite.com/，禁止使用 open.feishu.cn 等国内飞书接口。官方域名说明

1. 页面名称

风控管理 → Lark 通知 → Lark 人员。保持独立 PRD，本页只解决“CRM 管理人员是谁、对应哪个 Lark 用户、如何获取并保存 open_id”。

2. 页面目的

维护 CRM 管理人员 ↔ Lark 用户的绑定关系。绑定完成后，通知配置才能选择该人员；后续单聊消息使用所保存的 open_id。

3. 页面功能

  • 展示人员姓名、角色、CRM 邮箱、Lark User ID、绑定状态、更新时间及操作。
  • 新增已有管理人员；按 CRM 邮箱查询并绑定，支持重新获取、编辑和清空/解除绑定。
  • 本次只补充 PRD，不改页面，不接真实 API；原型手动填 ID 与 ou_demo_alex、ou_demo_winnie 等值继续保留。

Lark 人员绑定说明

正式系统由 CRM 服务端通过管理人员邮箱匹配 Lark 用户，调用 Open API 获取 open_id，成功后保存为 Lark User ID。无法获取时检查邮箱、应用权限与通讯录可见范围。演示 ID 不是真实绑定，正式开发不得写死或将其自动迁移为有效绑定。

官方开发文档统一列于本页底部；所有链接均直达 open.larksuite.com。查询、绑定和发送只使用本项目国际版 Lark 应用的凭证与用户标识。

5. 核心业务规则

5.1 ID 口径与绑定规则

  • CRM 的“Lark User ID”统一保存 Lark open_id，不保存 lark_id 作为通知接收 ID；邮箱、手机号、CRM 用户 ID、user_id、union_id 均不能替代该字段。后续一对一 Lark 消息以已保存的 open_id 作为接收用户标识。
  • open_id 是应用内用户标识，不能把应用 A 查询到的值直接交给应用 B 发送。查询、保存和发送须使用同一租户及同一应用上下文；更换应用需重新查询，不能直接复用旧值。官方用户标识说明
  • 一名 CRM 管理人员在当前通知应用内只维护一条绑定。不同 CRM 账号是否允许共用同一 Lark 身份尚待确认，不在本次自行扩展关联规则。
  • 目标用户匹配、返回成功且获得非空 open_id 后方可保存。仅 HTTP 成功、仅 code=0、仅看到 ou_ 前缀均不足以证明目标绑定成功。
  • 解绑后取消该人员在所有通知规则中的选择；已接入的 CRM 登录通知接收人也需同步移除。历史通知保留，重新绑定不自动恢复已移除的选择。

5.2 服务端获取 tenant_access_token

国际版 Lark 企业自建应用由 CRM 服务端读取服务端配置中的 App ID、App Secret 获取访问凭证：

POST https://open.larksuite.com/open-apis/auth/v3/tenant_access_token/internal
Content-Type: application/json; charset=utf-8

{
  "app_id": "<APP_ID>",
  "app_secret": "<APP_SECRET>"
}

该凭证代表应用调用服务端 API，最长有效期为 2 小时；服务端以响应中的 expire（秒）管理有效期和更新，不把每次返回值都当作新的两小时凭证。App ID、App Secret 和 tenant_access_token 由服务端配置与管理，不写死在前端代码，不在页面或浏览器存储中保存凭证。官方凭证文档

5.3 优先通过 CRM 邮箱查询 open_id

服务端读取该管理人员的 CRM 邮箱；查询参数放在 URL，凭证放在 Authorization 请求头：

POST https://open.larksuite.com/open-apis/contact/v3/users/batch_get_id?user_id_type=open_id
Authorization: Bearer <tenant_access_token>
Content-Type: application/json; charset=utf-8

{
  "emails": ["winnie@example.com"]
}

接口也支持手机号查询，参数示例为 {"mobiles":["13800000000"]}。这仅说明接口能力；本页面仍优先使用邮箱，不新增手机号录入或未经确认的自动兜底流程。非中国大陆号码的区号格式按官方接口文档处理。官方用户 ID 查询文档

5.4 读取返回值并保存

响应结构示意（ID 为占位值，不可直接用于生产）：

{
  "code": 0,
  "msg": "success",
  "data": {
    "user_list": [
      {
        "user_id": "ou_xxxxxxxxxxxxx",
        "email": "winnie@example.com"
      }
    ]
  }
}

当请求参数为 user_id_type=open_id 时，返回字段名仍为 user_id，其值实际是 open_id。将与本次查询邮箱对应项的该值保存到“Lark User ID”；不能不核对邮箱就取第一条，也不能在返回为空时保存占位 ID。官方返回 ID 类型说明

5.5 应用权限及后续消息使用

  • 申请并生效 contact:user.id:readonly（通过手机号或邮箱获取用户 ID），同时确认通讯录数据权限范围包含目标用户；发布/授权按企业应用要求完成。官方权限排查说明
  • 后续单聊发送使用应用机器人，需开启机器人能力，并开通 im:message:send_as_bot 等发送接口支持的适当权限；确认目标人员在应用可用范围内。查询到 ID 不等于一定能够发送消息。官方应用机器人配置说明、发送接口权限与前置条件
POST https://open.larksuite.com/open-apis/im/v1/messages?receive_id_type=open_id
Authorization: Bearer <tenant_access_token>

请求 Body 中：
receive_id = 已保存的 Lark User ID（open_id）

以上仅说明 ID 使用关系，不是完整发送请求；消息内容等必填参数由对应通知需求定义。本页不展开业务通知规则、模板、自动任务或重试方案。

6. 操作说明

CRM 管理人员 → 读取 CRM 邮箱 → Lark 国际版 Open API（服务端使用有效 tenant_access_token）→ 通过邮箱查询 Lark 用户 → 获取 open_id → 保存到 CRM“Lark User ID”→ 绑定状态＝已绑定

操作/结果页面及保存行为
新增 / 绑定选择已有人员；姓名、角色、邮箱自动带出且只读。点击绑定执行上述正式流程，成功后显示已绑定及返回的 open_id。重复人员提示“该人员已存在”。
编辑 / 重新获取仍针对同一 CRM 管理人员，按其当前 CRM 邮箱重新查询。成功保存后替换 ID，不能手输任意值覆盖正式结果；如邮箱错误，先在 CRM 原有资料中修正。
邮箱缺失 / 格式错误提示“请先完善 CRM 管理人员邮箱”，不调用人员查询、不生成或伪造 ID。
无匹配用户 / 返回空 ID提示“未找到 Lark 用户，请检查 CRM 邮箱与 Lark 账号邮箱是否一致”；本次绑定失败，首次绑定仍未绑定，不保存空结果为成功。
权限、凭证、网络或服务异常提示“Lark 用户查询失败，请检查邮箱或应用权限”；不把权限异常直接断定为用户不存在。
目标无法唯一确认提示核对邮箱和目标人员，不自动选择返回项，不保存候选 ID。
重新获取失败 / 保存失败保留原已保存绑定与更新时间，不用失败结果覆盖旧 ID，不显示更新成功。首次失败仍未绑定。
清空 / 解除绑定明确清空并成功保存后变为未绑定，同步移除后续通知对象；不删除 CRM 人员或历史通知。
取消放弃本次草稿/候选结果，不更新绑定或更新时间。

7. 状态说明

原状态触发条件结果
未绑定目标邮箱匹配、接口返回 open_id 且保存成功已绑定；可被通知配置选择，记录更新时间。
未绑定查询无结果、失败、ID 为空或保存失败仍未绑定；显示原因，不保存无效值。
已绑定重新获取到目标 open_id 并成功更新仍已绑定；实际 ID 变化时更新更新时间，后续使用新值。
已绑定明确清空并成功保存未绑定；ID 为空，通知对象同步取消。
已绑定查询更新失败、保存失败或取消保留原绑定，不以瞬时失败清空既有关系。

查询中的等待/失败提示属于操作反馈，不新增“绑定中 / 绑定失败”持久状态。原型非空演示文本显示已绑定只用于演示，不能作为生产环境有效性依据；“已绑定”也不保证未来消息一定发送成功。

8. 验收标准

  1. CRM 管理人员、角色和邮箱均来自 CRM，只读；同一人员不能重复新增。
  2. 正式查询固定 user_id_type=open_id；准确匹配邮箱后保存响应 user_id 的实际 open_id，不混入其他 ID 或写死演示值。
  3. 首次查询失败/空结果不绑定，更新失败不覆盖旧绑定；成功变更才更新时间；解除绑定同步移除通知对象。
  4. App ID、App Secret 等配置由服务端管理；查询及发送只调用 open.larksuite.com，使用同一国际版租户和应用，发送时 receive_id_type=open_id。
  5. 底部五个开发文档入口均指向 open.larksuite.com；不保存 lark_id 为接收 ID；ou_demo_alex、ou_demo_winnie 仅用于演示，正式环境不得使用。

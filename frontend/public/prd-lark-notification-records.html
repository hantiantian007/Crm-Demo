通知记录 - PRD

业务流程

本图仅为现有本地模拟流程：“已发送”不代表真实送达，失败记录也只是演示结果；不包含真实业务事件或网络请求。 窄屏可在图内横向滚动查看。

1. 本次调整目的

查看什么时候、因为什么业务、向哪些 Lark 群组通知及结果。

2. 新增/调整内容

  • 列表展示通知时间、通知类型、内容、接收群组、发送状态、失败原因及查看入口。
  • 分页及只读详情；保留手动模拟发送，仅使用通知配置提供的当前规则，本页不另行定义场景。

3. 核心字段定义

String[] 为去重的群组标识数组，名称仅作展示；空数组为 []。DateTime 展示 YYYY-MM-DD HH:mm:ss（19字符），原型取本机时间，正式使用 CRM 统一时区。缺失值显示“—”。所有发送结果均为本地演示，不接 Lark API 或真实业务事件。

字段名称字段含义数据来源数据类型字符/格式要求状态/枚举默认值是否必填是否可编辑业务规则 / 何时变化
通知时间本次记录生成时间系统生成；原型为手动模拟时刻DateTime19字符，不可空无生成时刻是否创建后固定，不随配置或群组变更改写。
通知类型 / 名称对应规则或历史业务名称通知配置；历史名称快照String非空；沿用现有名称，建议≤100字符通知配置中的当前规则及历史名称快照来源快照是否旧出金、异常登录、高风险样例名称不变，不据此新增规则。
通知内容完整消息正文业务事件数据；原型为既有演示文本String非空；保留换行；建议≤4000字符无事件正文是否表格省略、详情全文；保留现有演示记录内容。
接收群组 / 通知群组当次选择的启用群组规则的群组配置；登录通知使用该用户的群组配置String[] 名称快照支持多个群；空数组表示无有效目标无生成时的群名称快照有效发送至少1群；失败记录可空否改名、停用或删除群组不修改历史。旧单聊记录群组为空并提示“旧记录未配置群组”，不把人员姓名伪装成群名。
发送状态模拟投递结果前端演示流程String固定枚举，不可空已发送 / 发送失败生成后按结果确定是否已发送只代表模拟成功，不代表真实送达或已读；无群组模拟为失败。
失败原因本次未成功的说明演示资格检查或预置演示数据String失败必有；成功为空；建议≤500字符无空字符串失败时必填否详情和列表可查看；不包含 Webhook 或凭证。
查看详情只读展示完整记录当前行记录UI操作打开现有弹窗查看 / 关闭查看系统提供否不修改或重发历史，不新增页面。

4. 核心业务规则

  • 默认进入通知记录；保留原记录编号、时间、类型、正文及结果。新记录接收对象为群组快照，旧单聊记录明确标识为历史迁移记录。
  • 模拟按钮只生成本地结果；规则停用时禁止模拟且不新增记录；启用但无有效群组时记录演示失败。
  • 本页不增加真实发送、自动重试、检测规则、模板或新场景；Webhook 不出现在记录及失败原因中。

5. 操作说明

查看打开详情，关闭不改变记录。模拟发送选择启用规则，读取其当前有效群组，生成新记录后回到第一页。分页仅改变展示。

6. 状态说明

已发送＝演示成功；发送失败＝演示失败。旧单聊记录的“群组未配置”为迁移说明，不是新增发送状态。

7. 验收标准

  1. 默认 Tab 为通知记录，分页和完整详情可用。
  2. 旧记录的时间、内容和结果保留；旧人员不作为群组显示。
  3. 模拟成功/失败均有明确演示说明，停用规则不能模拟。
  4. 群组改名、删除后历史快照不变；不执行网络发送。

本期仅前端原型和本地演示数据；不接真实 Lark API、不发送消息、不增加业务场景。正式环境的 Webhook 和敏感信息由后端安全保存，不写入前端代码或浏览器存储。

本文件只定义出金审核详情新增的风险辅助评估，不重复描述已有出金功能。依据《CRM/MT 交易服务系统安全能力建设需求文档》及源码盘点。本阶段为前端演示设计，固定风险案例不代表真实检测；正式风险快照、权限校验和审计持久化由服务端实现。本次交付仅为 PRD，不代表下述能力已经开发。

1. 前置条件：准确关联申请与客户

  • 以出金申请 ID 唯一定位申请，再读取该申请对应的 CRM 客户及 MT 账号；同一 MT 账户的多笔申请不得混淆。单独的账号参数不能作为唯一申请标识。
  • 当前源码存在传入 account=8110474 却回退显示其他默认账户资料的问题，必须先修复关联，才可接入风险展示。
  • 申请不存在、标识不足或申请与客户/账号不一致时，显示加载失败及可理解的原因，不得回退其他客户资料，也不得沿用上一次客户的风险结果。
  • 身份关联失败时不生成可信风险结论；风险信息必须能追溯到本次申请及对应客户。

2. 新增风险摘要及核心字段

右侧“风险提示”卡片仅展示风险等级、命中风险数量、系统审核建议及“查看风险明细”按钮。点击按钮在当前页面打开“出金风险明细”弹窗，不跳转、不修改路由，也不再滚动定位左侧区域。

左侧不再独立展示风险核查区域，资金信息下方直接展示原有入金记录。弹窗按“风险摘要 → 风险命中明细 → 风险事件时间线”展示；摘要、明细与时间线共用同一份当前申请数据。

复用现有 Dialog，居中显示，桌面端最大宽度约 920px，整体最大高度为视口的 85%，超出内容在弹窗内部滚动；窄屏自适应，无横向溢出。支持右上角关闭、Esc 关闭及关闭按钮；每次打开显示当前申请，关闭不影响原有审核操作。

4. 风险时间线与人工核查暂缓说明

  • 风险时间线展示本次申请相关的收款账户变更、身份信息变更、异常登录/设备变化、关联风险事件及本次出金申请。按事件发生时间先后排序，同时间事件保留各自标识；缺失时间不得编造排序时间。
  • 风险事件时间线位于风险明细弹窗内，与右侧原有审核操作时间线分开，不覆盖原来的审核过程；时间线查看依据复用同一条风险记录，不重复构造事件。
  • 命中风险后展示风险等级、命中规则及依据，审核人员查看后按原有权限进入出金审核流程；不要求先完成独立人工风险核查。
  • 暂缓实施：人工核查表单、核查状态选择（待核查 / 核查中 / 核查完成）、核查说明、保存操作及历史核查记录展示。本期不提供这些入口，也不作为本期验收内容。
  • 已有 localStorage 演示核查历史不主动清空、不新增或覆盖；仅停止独立人工核查流程及展示。原有出金审核通过、驳回、权限和审核操作时间线不变，不因无人核查而将风险自动改为正常。

5. 风险快照、异常处理及业务边界

  • 按出金申请生成风险快照，保存命中规则、判断依据、评估时间及版本。重新评估保留历史；同一申请同一规则不得重复生成相同风险事件，新版本可引用既有事件。
  • 数据失败、来源缺失或无法支持完整判断时展示“风险评估不可用”，提示核实；风险等级为待核实，无法确认的命中总数显示“—”，不得自动归为低风险或用 0 表示无命中。
  • 历史快照可查看，但不能将旧结果伪装为本次成功评估；失败时已存在的核查历史继续保留。
  • 本次是风险辅助评估，不替代原有审核权限；大额出金提醒与高风险认定独立，单条规则不直接认定客户违规。
  • 不自动冻结资金、不自动拒绝出金、不修改 MT5 账户资金，也不自动执行暂停或二次审批。具体映射、拦截及升级策略未确认前不得擅自补充。
  • 本阶段仅设计前端演示的可用、命中和不可用场景。正式风险读取、快照保存、访问权限及审计持久化由服务端实现，不把本地演示记录当作真实安全控制。

7. 验收标准

  1. 同一账户多笔申请按申请 ID 分别加载正确客户及 MT 账号；覆盖 8110474 案例。记录不存在或关联不一致时加载失败，不显示其他客户默认资料。
  2. 数据正常未命中、命中风险、风险数据不可用三种场景清楚可区分；不可用不显示低风险或以 0 掩盖缺失。
  3. 摘要与同一快照的明细一致，规则计数去重；待确认映射不变成硬编码的正式判断。
  4. 五类风险的演示依据可追溯；明细能查看有效证据，缺失证据有明确提示，不产生无效链接。
  5. “查看风险明细”打开居中弹窗，不改变路由、不定位左侧区域；可关闭并再次打开当前申请，超长内容内部滚动、窄屏无横向溢出。弹窗风险时间线按事件时间排序，与明细共用数据，与原审核时间线分开。
  6. 重新评估后旧快照仍保留，同一命中不重复生成相同事件。人工核查表单、核查状态及历史记录展示暂缓，不作为本期验收内容；已有本地核查历史不主动清空，本期不产生新核查记录。
  7. 原有通过、驳回及审核权限不受影响，无自动冻结、拒绝或 MT5 资金操作，大额提醒不直接认定高风险。
  8. 文档和演示明确区分合成数据与正式安全能力；生产阈值及未确认规则保持待确认标记。

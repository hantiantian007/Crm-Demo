通知配置 - PRD

1. 页面名称

风控管理 → Lark 通知 → 通知配置。

2. 页面目的

确定现有 10 条业务规则通知谁、是否启用，不开发真实检测规则。

3. 页面功能

  • 列表展示名称、说明、通知人员、启用状态和设置入口。
  • 设置多个已绑定接收人员及启用/停用。其余字段为固定说明或只读配置信息，不增加规则编辑器。

4. 核心字段定义

定义口径：数据来源指业务来源，不指定数据库表或接口。带“建议”的长度为待确认约束，现有原型未见对应限制；沿用 CRM 主数据的字段不在本页截断或重写。String[] 表示去重的人员标识列表，空列表为 []，不以逗号拼接姓名代替标识。DateTime 统一展示 YYYY-MM-DD HH:mm:ss（19 字符）；正式时区沿用 CRM 统一口径，具体时区待确认，原型使用本机时间。显示“—”表示缺失，不作为实际字段值。

字段名称字段含义数据来源数据类型字符/格式要求状态/枚举默认值是否必填是否可编辑业务规则 / 何时变化

  • 以上 10 条规则原样沿用；每条独立配置，不新增场景。
  • 业务事件满足对应规则且规则启用、有有效人员时才通知；停用或无人不产生实际通知。
  • 启用默认只适用于新配置；不能覆盖用户已经保存的停用状态。
  • 解绑人员从所有规则中移除；重新绑定不自动重新勾选。
  • 通知级别尚未定案，不承担频率、升级或接收人自动分配功能。

6. 操作说明

“设置”回填人员和启用状态；名称、场景、说明及条件只读。保存成功后更新列表及时间，取消不改变配置；保存失败提示且不得显示为已持久保存。

7. 状态说明

状态判断 / 转换结果
启用新配置默认为启用，或管理人员由停用切换为启用并保存满足业务条件且有人员才发送；不补发停用期间事件。
停用管理人员关闭并保存后续事件不产生新通知；历史记录保留。
通知人员为空允许保存 []，不是第三种启用状态启用状态保持原值，但没有有效对象时不发送。
通知级别未设置当前没有确认的等级不当成低风险、不推断等级；后续枚举需单独确认。

当前原型状态固定显示“已开启”，没有规则开关、级别或时间字段。启用/停用与时间记录是文档研发目标，未修改现有实现。

8. 验收标准

  1. 固定展示 10 条规则，名称和说明不随人员设置改变。
  2. 可选择多个已绑定人员；解绑后同步移除。
  3. 启用/停用可独立保存，刷新保持；停用或无人不发送。
  4. 首次设置时间只赋值一次，更新时间随成功变更更新，取消/失败不更新。
  5. 无通知级别定义时显示未设置，不提供虚构选项。

本轮仅维护本页 PRD，不修改原型业务功能、数据或查看入口；研发目标不代表原型已实现。不设计 API 或数据库表结构。

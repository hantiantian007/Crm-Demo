2. 核心业务规则

风险类型触发条件
收款账户近期变更出金申请前 48 小时内修改钱包或银行卡。
身份信息近期变更出金申请前 24 小时内修改手机号、邮箱或密码。
异常登录或设备变化存在与本次出金相关的有效异常登录安全事件；不能仅凭普通 IP 变化或任意设备变化直接判定。

时间窗口以出金申请时间为基准向前计算；48 小时、24 小时为正式生产前待业务确认的建议窗口。

风险等级衡量标准

等级衡量标准及示例
低风险当前出金申请风险数据完整，未命中任何有效基础风险规则（N = 0）。
中风险至少命中一类有效基础风险，但未满足高风险组合条件。
例如：仅收款账户变更、仅身份信息变更、仅异常登录，或身份信息变更 + 异常登录。
高风险同时满足 A：近期收款账户变更；B：近期身份信息变更或异常登录/设备变化至少一类。
高风险 = 收款账户变更 AND（身份信息变更 OR 异常登录/设备变化）。
例如：修改收款银行卡 + 异常登录、修改收款钱包 + 修改登录邮箱，或三类风险同时命中。
待核实当前申请与客户关联不明确，或关键风险数据缺失、读取失败，无法可靠评估；优先于其他等级，命中数量显示“—”，不得判为低风险。
  • 仅判断上述三类基础风险；N 为有效风险的去重类别数（Integer 0–3）；同类多条事实记录保留，但只计一类，“多项命中”不另计类别。
  • 整体等级按类别组合计算，不取单条事件的最高预置等级；三类风险单独命中均为中风险。
  • 数据来自当前申请对应的收款/身份变更及有效登录事件，必须校验申请、客户、MT账号归属，不回退其他客户资料。
  • 出金金额大不自动判高风险；本期不包含“高风险关联账户”识别；不可用不得显示低风险或以 0 掩盖缺失。
  • 整体等级必须可追溯至实际命中的风险类型及事件记录；风险摘要与弹窗共用同一结果，整体等级和命中数量保持一致。
  • 仅作风险提示，不自动冻结、拒绝或放行，不增加人工核查流程，不改变原审核权限。

字段只读；原始事实对应本次申请的 MT 账号或业务记录。时间为 YYYY-MM-DD HH:mm:ss，缺失显示“—”，不编造事件或时间。无事件显示空态；数据不可用不展示事件；无风险但申请明确时可展示申请事件。

测试条件预期结果

数据无法获取 / 缺失 / 归属不明待核实，数量“—”，不判无风险、不展示其他客户事件。
同一类异常登录重复出现（其他类别同理）只计一类，单类仍为中风险，不因此升级为高风险，事实明细不丢失。
对照右侧摘要与弹窗等级、数量一致；仅有效三类风险参与计数。
切换申请或传入不匹配账号只展示归属明确的当前申请风险，不借用默认客户风险。
查看弹窗及时间线风险事实和描述直接展示，时间顺序正确，无审核建议、依据查看及内容折叠按钮。
打开、关闭、再次打开弹窗正常显示当前申请；原有审核通过、驳回和权限不受影响，无资金操作。

待确认事项：生产时间窗口、边界及业务时区；安全事件与当前出金申请、客户及 MT 账号的关联口径中尚未确认的部分，不自行补造。

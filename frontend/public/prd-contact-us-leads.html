联系我们表单及留资接入 PRD

本期仅为 CRM 前端演示：未接入真实微信公众号、微信网页授权、OpenID 或后端服务。提交仅在当前浏览器、当前站点保存，不代表真实微信用户提交，也不会跨浏览器或跨项目传输。

1. 页面说明

页面：联系我们；菜单：其他页面 → 联系我们；路由：/other/contact-us。页面顶部沿用 CRM 的 PRD 查看入口。

用途：演示用户填写联系方式及咨询留言，生成现有留资列表中的待分配记录，再复用分配、跟进和详情流程。

结构：沿用提供的 HATC 表单参考图，保留品牌标识、浅色表单、绿色提交按钮和页脚。按姓名、手机号码及区号、微信号、邮箱、留言、提交的顺序展示；不增加上传或其他表单。

2. 核心字段定义

必填依据参考图：姓名、手机号、邮箱必填，留言选填；微信号按本次需求必填。必填文本去除首尾空白后校验。除已明确的留言上限外，不新增名称、微信号字符集或长度业务限制。

字段 / 含义数据来源及映射类型 / 字符格式必填 / 默认值编辑及业务规则
姓名
提交人的姓名		用户手动输入 → 留资客户名称 nameString；保留中文或其他文字；去首尾空白必填，默认空提交前可编辑；不得为空或仅空格；具体长度及特殊字符限制待确认，不自行增加。
手机号码及区号
原始联系方式		用户选择区号并填写号码 → countryCode、phoneNumber；合并到 phoneString，不转数值；区号为“+”及数字；展示为“+区号 空格 号码”，保留号码内部空格、前导零等原始格式均必填；默认区号 +86，号码空提交前可编辑；区号复用现有注册资料选项 +86、+84、+852、+82、+81、+66、+65；号码不能为空。不新增某国位数或真实性校验，完整国家选项及号码格式规则待确认。

3. 提交流程

  1. 填写表单，校验姓名、号码、微信号、邮箱非空，校验邮箱基本格式及留言长度；各字段下展示明确错误。
  2. 校验通过后调用现有 leadsDemo.js 的提交入口，生成唯一留资 ID，记录系统时间和原始提交快照；每次有效提交独立成条，不按姓名或邮箱自动覆盖已有记录。
  3. 写入现有本地存储成功后才提示“本地演示留资提交成功”，清空表单；提交过程中按钮不可重复点击。保存失败不清空填写内容。
  4. 到客户管理 → 留资列表，在“全部 / 待分配”及公众号来源筛选中可查到记录，按现有流程分配及跟进。

4. 留资关联及原始信息保护

  • 列表、详情和本表单共用 leadsDemo.js 与 crm-leads-demo-v1 存储，不建立独立留资体系；同一站点刷新后仍可读取，清除浏览器存储会丢失演示操作。
  • 姓名→客户名称；完整区号及号码→联系方式；微信号→微信字段；邮箱→客户邮箱；留言→咨询内容；提交时间→申请时间；来源→微信公众号-联系我们。
  • 沿用现有结构，查询分类归“其他”，留资次数为 1，无跟进记录、归属或转化账户；不新增状态、审批或分配规则。
  • 详情基础信息展示完整微信号；“留资记录 → 原始提交信息”同时提供只读原始微信号、姓名、区号、联系方式、邮箱、完整留言、来源和时间。
  • 后续分配、跟进、基础联系方式修改不得改写原始提交快照；原始字段与当前资料分开保存。旧记录未提供微信号时标注“原记录未提供”，不伪造历史数据。
  • 其他来源继续使用原流程；不新增“联系我们记录”菜单或另一个管理列表。正式接入需后端接收公众号提交并提供 CRM 查询，本期不实现。

5. 异常处理

  • 必填项为空或仅空格、邮箱格式错误：显示对应字段错误，禁止创建留资；微信号不要求登录微信或授权。
  • 留言超长：输入限制至 500 字；绕过页面提交的超长内容由共享保存入口拒绝，不截断已经保存的历史留言。
  • 本地存储禁用、空间不足：提示提交失败并保留表单；不显示成功，不追加内存中的虚假成功记录。
  • 已有演示数据损坏：提示读取失败，不覆盖或重置原存储；当前输入保留，修复存储问题后可重试。

6. 验收标准

  1. 菜单打开独立联系我们页，字段顺序与参考图要求一致，微信号位于手机号码之后；留言选填并计数，无上传功能。
  2. 微信号空/仅空格不能提交；姓名、手机号、邮箱必填，格式错误明确提示；500 字留言可保存，超长禁止持久化。
  3. 提交成功后同一份共享留资数据新增唯一记录，来源正确、默认待分配，完整区号/微信号/留言/时间可查，刷新保留。
  4. 分配和跟进后列表详情同步；修改当前联系方式不会改写原始提交，其他来源记录保持不变；存储失败不丢失输入、不冒充成功。
  5. 页面及文档明确为前端演示；未连接真实微信、OpenID、网页授权或后端；只新增本 PRD，沿用现有 PRD 查看交互。

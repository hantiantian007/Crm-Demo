CRM 密码安全与风险触发强制重置

目标：降低泄漏密码继续被使用风险；避免 VPN/移动网络引发误拦截；风险事件可通知内部并保留审计。

范围与触发

  • 强制改密生效：下次登录（不要求立即踢下线）。
  • 全局阻断：未完成改密前，不能访问 CRM 任何业务页面与功能，仅允许登录、验证码与改密交互。
  • IP/VPN/设备变化仅作为风险信号，不可单独作为强制改密条件。

强制改密覆盖范围（V1.0.0）

条件 要求
账号类型 标准
业务身份 代理 或 直客
不参与范围强制 系统账号（后台管理员）；标准账号但非代理/直客的其他用户类型

强制来源

  • 范围强制：管理员发起一次性安全升级，覆盖标准账号中的代理与直客。
  • 单账号强制：管理员对指定标准账号（代理/直客）设置“下次登录必须改密”。

邮箱验证码（V1.0.0）

  • 有效期：10 分钟；发送冷却：60 秒；失败次数：5 次后进入限制状态（演示）。
  • 演示阶段不接入真实邮箱服务，页面交互与状态变化保持完整。

风险事件与 Lark 通知（V1.0.0）

  • 有风险事件即生成 Lark 通知记录；推送对象从数据库配置读取（演示）。
  • Lark 通知失败不影响强制改密主流程；失败可重试（演示）。
  • Lark 卡片操作不能绕过 CRM 权限与业务状态校验（演示提示）。

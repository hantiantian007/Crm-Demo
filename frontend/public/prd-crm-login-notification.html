CRM 登录通知配置 - PRD

1. 页面名称

系统管理 → 系统设置 → 用户管理 → CRM 登录通知配置弹窗。

2. 页面目的

指定 CRM 用户成功登录 CRM 后，通知配置的管理人员，使其知道该用户发生了 CRM 登录；不把登录直接认定为异常。

3. 页面功能

  • 显示所选 CRM 用户身份和最近登录时间。
  • 开启/关闭登录通知，选择一个或多个已绑定管理人员。
  • 保存、取消配置，显示配置状态及更新时间。

5. 核心业务规则

  • 核心触发：指定 CRM 用户成功登录 CRM → 读取该用户配置 → 已开启且有有效管理人员 → 分别发送 Lark 单聊通知。仅针对 CRM，不涉及 MT5。
  • 不开启、不配置人员或所有人员均未绑定时不发送。无人员可保存，但状态为待配置；绑定后不会自动恢复之前移除的人员，需要重新选择保存。
  • 接收人使用配置的已绑定管理人员，不自动通知用户本人；客户与管理人员使用各自 CRM 身份。
  • 关闭可以保留接收名单以便重新开启，但不继续发送；发送前按最新开关与绑定情况检查。
  • 通知至少包含登录人员、登录时间；记录用户、接收人、通知内容和发送结果。失败不改变用户登录成功结果，也不改配置开关。
  • 最近登录时间反映最新登录；通知内容使用本次事件快照，不能因下一次登录而串改。

6. 操作说明

从用户列表进入后只读回填身份；修改开关和接收人并保存成功才生效。取消/关闭不保存草稿。清空接收人后保存为无对象；开启时显示待配置。人员绑定到 Lark 人员页面维护，本弹窗不填写客户本人 Lark ID。

原型目前为客户本人通知且无真实登录事件。本版描述“CRM 用户登录 → 配置的管理人员接收”的研发目标。新增配置状态、时间及管理人员多选不在本轮实现。

8. 验收标准

  1. CRM 用户、邮箱/账号、ID 只读，配置不会保存到其他用户。
  2. 新配置默认关闭，可多选已绑定管理人员，未绑定不可选。
  3. 开启且有有效接收人时，只有该用户 CRM 成功登录才触发；关闭/无人/MT5 登录均不触发。
  4. 保存后状态及更新时间正确、刷新保持；取消/失败不覆盖成功配置。
  5. 通知包含该次登录人员和时间，发送结果可追溯，不用最近登录字段覆盖事件内容。

本轮仅维护本页 PRD，不修改原型业务功能、数据或查看入口；研发目标不代表原型已实现。不设计 API 或数据库表结构。

CRM 用户列表 - PRD

1. 本次调整目的

从现有用户列表进入按用户配置的 CRM 登录群通知，不改变账号、MT账户或客户登录日志。

2. 新增/调整内容

  • 登录双重验证后的“登录通知”可点击设置；原设置按钮仍进入相同弹窗。
  • 用户详情展示当前通知群组，个人绑定状态不再显示。

3. 核心字段定义

String[] 为去重的群组标识数组，名称仅作展示；空数组为 []。DateTime 展示 YYYY-MM-DD HH:mm:ss（19字符），原型取本机时间，正式使用 CRM 统一时区。缺失值显示“—”。所有发送结果均为本地演示，不接 Lark API 或真实业务事件。

用户名称所选 CRM 用户姓名现有 CRM 用户数据String非空；长度沿用主数据无所选用户名称是，来源否不在登录通知配置中编辑。

4. 核心业务规则

  • 本页读取登录通知配置及有效群组，不维护群组。配置的选择、保存与失效处理规则见独立《CRM 登录通知配置 PRD》；列表展示最新保存的配置。
  • 旧个人接收人配置无法推断对应群组，不自动转换；旧本地数据保留，新配置须重新选择群组。
  • 旧个人通知开关保留，个人 ID 不作为群组；迁移后无群组时显示待配置，引导管理员选择群组。

5. 操作说明

设置打开独立登录通知弹窗；取消无更改，保存同步当前用户状态和群组。本页不触发模拟/真实登录，也不新增通知场景。

6. 状态说明

列表显示已开启 / 未开启；配置弹窗显示已关闭 / 待配置 / 已配置。开关开启不等于消息已发送。

7. 验收标准

  1. 新增通知状态对应正确用户，已开启/未开启与保存值一致。
  2. 点击登录通知或设置可配置同一用户，查看能看到群组。
  3. 不同用户独立保存，刷新保持；无需个人 Lark ID。
  4. 群停用/删除后不再作为目标，开启且无人可收时为待配置。

本期仅前端原型和本地演示数据；不接真实 Lark API、不发送消息、不增加业务场景。正式环境的 Webhook 和敏感信息由后端安全保存，不写入前端代码或浏览器存储。

CRM 用户列表 - PRD

1. 页面名称

系统管理 → 系统设置 → 用户管理。直接打开现有用户列表，不新增“用户列表”菜单。本 PRD 聚焦列表中的 CRM 登录通知配置入口及状态。

2. 页面目的

在用户列表为指定 CRM 用户开启或关闭登录提醒，并明确通知哪些管理人员。

3. 页面功能

  • 保留原有用户字段、搜索、筛选、查看和分页。
  • 显示 CRM 登录通知开关及配置状态；提供按用户配置接收人的入口。
  • 新增配置相关信息在现有列表/设置中展示，不改变用户账号本身。

5. 核心业务规则

  • 默认关闭仅适用于尚无配置的用户；读取已有配置时不得覆盖历史开关或人员。
  • 指定 CRM 用户成功登录 CRM 后，开关开启且存在有效接收人时，才通知其配置的管理人员。不是 MT5 登录，也不限于管理人员账号登录。
  • 未开启或未配置有效人员不发送；配置状态按开关和有效人员即时推导。
  • 配置与用户身份绑定，不能通过改名、排序或翻页串到其他行。
  • 原有用户类型、MT账户数量、登录状态、双重验证、最近登录信息等业务字段保持来源和现有规则不变。

6. 操作说明

点击当前行“CRM 登录通知配置”或登录通知状态打开同一设置弹窗；保存成功更新该行状态，取消不改动。名单、开关与更新时间同步保存，失败不能提示为已保存；原有查看、搜索、重置和分页继续保留。

7. 状态说明

配置状态判断规则何时变化
已关闭登录通知开关为 false，与名单是否为空无关关闭并成功保存后进入；保留原名单但不发送。
待配置开关为 true，但有效已绑定接收人为 0开启且保存空名单，或最后一位有效接收人解绑后进入；不发送。
已配置开关为 true，且有至少 1 位有效已绑定管理人员成功保存有效名单后进入；仅在指定用户成功登录 CRM 时发送，不表示已发送成功。

配置状态是本版明确的产品定义。现原型只有开关及客户本人 Lark ID，尚无管理人员多选、配置状态或更新时间；这些内容需要后续研发，本轮不改原型。

8. 验收标准

  1. 每行通知配置关联正确 CRM 用户 ID，原有字段和功能不变。
  2. 未配置默认关闭；已保存开关、接收人刷新后保持，不被默认值覆盖。
  3. 可为用户设置多个已绑定管理人员；保存只更新当前用户。
  4. 三种配置状态按规则显示；解绑导致无人时变为待配置，不发送。
  5. 取消/保存失败不冒充成功；成功变更更新时间正确。

本轮仅维护本页 PRD，不修改原型业务功能、数据或查看入口；研发目标不代表原型已实现。不设计 API 或数据库表结构。
